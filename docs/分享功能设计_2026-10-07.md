# 人设卡分享功能 · 设计方案

日期：2026-10-07
状态：待用户确认方案后实施

---

## 一、现状（问题诊断）

### 1.1 分享按钮形同虚设
`PreviewView.vue` 顶栏有一个「分享」按钮，逻辑是：

```js
await navigator.share({ title, text, url: window.location.href })
```

问题：**在 Capacitor APP 里 `window.location.href` 是 `http://localhost`（或 `capacitor://localhost`）**，分享出去别人根本打不开。这个按钮等于没功能。

### 1.2 没有视觉卡片导出
人设卡只存在于 APP 内，无法变成一张图片发出去。而「二次元扩列」场景里，**图片才是真正的流通单位**（发群里、发朋友圈、发给同好）。

### 1.3 没有公网部署
项目目前无任何公网 URL（vercel.json / _redirects 已备好但未部署）。所以「分享链接」暂时无法落地。

### 1.4 使用的卡片组件是旧设计
`PreviewView` 用的是 `CardPreview.vue`（tailwind 老样式：`glass-card`），而用户现在的人设卡设计在 `ProfileView.vue` 的 `cs-card`（MUJI 竖版卡）。两套不一致。

---

## 二、设计目标

> 让人设卡可以被「分享出去」——发到微信 / QQ / 群 / 朋友，对方能看到你的卡。

约束（来自产品三条底线与现状）：
- 不碰钱
- 分享出去的卡必须是**公开态**，不含联系方式（隐私）
- 优先在 APP 内闭环（不依赖部署）

---

## 三、三种分享形态

### 形态 A：图片分享（P0 · 推荐先做）
把卡片渲染成一张竖版 PNG，走系统分享面板发给微信/QQ。

- **技术**：`html-to-image`（toPng 截取卡片 DOM）→ Blob → `@capacitor/share`（share files）；Web 环境兜底 `navigator.share` 或下载
- **优点**：不依赖部署、离线可用、图片在任何 App 都能看
- **成本**：装 `html-to-image`（纯 JS，无需原生同步）；若要系统分享面板装 `@capacitor/share` + `@capacitor/filesystem`（需 cap sync + 重打包）
- **兜底**：若无原生插件，用 `<a download>` 存到相册/下载目录

### 形态 B：链接分享（P1 · 需部署）
部署 dist 到 Cloudflare Pages（免费，用户已有账号）→ 得到 `https://xxx.pages.dev`。

- 生成 `/card/:userId` 分享链接，别人浏览器打开即看卡（公开读页面/弹窗）
- **优点**：点击即看、数据实时、可更新
- **缺点**：依赖部署；需要做「公开读单张卡」的页面与权限
- **成本**：部署 0.5h + 公开卡页 1.5h

### 形态 C：文本分享（P0 · 最简单）
复制卡片摘要文本到剪贴板，粘贴到任意地方。

```
阿宅喵 #A3F2K9
MBTI INTJ · 上海
兴趣：插画 / 深渊 / 同人
想认识：同担、画师
```
- **零依赖**，5 分钟可做

---

## 四、推荐路线

**P0 = 形态 A（图片分享）+ 形态 C（文本分享）**
**P1 = 形态 B（链接分享，等部署）**

理由：
- A 满足核心场景（发图给同好），且不依赖部署
- C 成本极低作为随时可用的补充
- B 价值最高但卡在部署，等用户决定

---

## 五、需要用户拍板的决策点

1. **分享形态范围**：
   - 只做 A + C（不依赖部署，今天可完成）
   - 还是 A + B + C 全做（需先部署 Cloudflare Pages）

2. **图片分享落点**：
   - 走系统分享面板（装原生插件，可发微信/QQ）—— 体验最好
   - 还是只做「保存到相册/下载」（零原生依赖）—— 最快

3. **卡片设计统一**：
   - 导出统一到**当前人设卡设计**（ProfileView cs-card，MUJI 竖版）—— 建议
   - 还是保留旧 CardPreview

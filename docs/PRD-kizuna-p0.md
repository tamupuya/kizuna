## 2. 项目背景与目标

### 2.1 背景

二次元用户（ACG 爱好者）在现实中存在强烈的"扩列"（扩大同好社交圈）需求，但现有工具存在三处断层：

1. **认识难**：漫展/线下活动人流量大，但缺乏"谁和我同场、谁和我同好"的有效信号，现场擦肩而过却无法建立连接。
2. **信息乱**：漫展信息分散在小红书、微博、贴吧，真假混杂、过期信息多，缺少一个可信、可维护、实时同步的活动信息源。
3. **交易险**：二手谷子交换（出/求/换）主要靠闲鱼、微信私下交易，存在信任成本高、售后纠纷难处理、隐私（联系方式）易被骚扰等问题。

本产品定位为**泛二次元社区信息基础设施**：以"人设卡 → tag 数据 → 漫展雷达 → 中谷店"为核心链路，第一步从**漫展单场景**切入，验证最小闭环。

### 2.2 产品目标

**一句话目标**：让 ACG 同好在漫展场景下，能"找到彼此、认识彼此、安全地交换物品"。

**P0 阶段目标（可衡量）**：

| 目标 | 衡量指标（见第 9 章埋点） |
|---|---|
| 打通"人设卡 → 雷达 → 中谷店"单场景闭环 | 三模块端到端可用，用户可完成一次完整链路 |
| 建立可信的活动信息源 | 漫展数据可被管理员维护并实时同步到 App |
| 降低交易信任成本 | 中谷店挂出→申请→（私下）成交流程可走通 |
| 验证产品核心假设 | "同好之间需要更高效的初次连接工具"假设得到行为数据支撑 |

### 2.3 非目标（明确不做，见 3.2）

## 3. 产品范围

### 3.1 明确要做（P0）

**三大模块**：

1. **人设卡**（单边体系，只面向用户）
   - 基本资料：CN/昵称、6 位编号、性别、活动地区、签名（bio）、头像
   - 圈内身份（≤3 个多选）、现实身份（单选）
   - MBTI（16 种）、星座（12 种）
   - 兴趣图鉴（18 分类 + 避雷 NG，三态管理）
   - 扩列意图（想认识的人 / 想一起做的事 / 我能提供）
   - OC 卡（自设角色卡，可多张）

2. **漫展雷达（同窗会）**
   - 漫展列表（网络数据 + 离线缓存）
   - 漫展详情页：想去 / 在场确认（日期 + 时段）
   - 同窗会（短时临时匹配房间）：发起（时间窗 / 意图 / 线上或线下 / 可选密码）、加入、聊天、解散/退出
   - 匹配推荐（首页 banner）

3. **中谷店**
   - 挂出谷子（出/求/换 + 图片 + IP 标签 + 交易方式 + 退换政策 + 收款码）
   - 广场浏览（搜索 + 5 tab 分类 + 双列网格）
   - 关注系统（关注特定用户，第一时间看到其挂出）
   - 交易状态机（拍下→发货→收货→完成 / 申诉）

### 3.2 明确不做（P0 及长期）

| 禁止项 | 原因 |
|---|---|
| 关注/粉丝系统（社交关注） | 禁止社交动态化，仅保留中谷店"关注卖家" |
| 朋友圈 / 动态 / 帖子 | 产品不做社交 feed |
| 直播 / 短视频 | 超出范围 |
| "立即购买/去付款"按钮 | 平台不碰资金，UI 禁用 |
| 资金托管 / 担保交易 | 底层原则"不碰钱、不做闲鱼式交易" |
| 关注/粉丝经济 | 不做粉丝体系 |
| 复杂匹配筛选面板 | 雷达追求简单，不做重型筛选 |
| "交换人设卡"门控 | 改为单向分享即可看（L1），不设门控 |
| 引导页 | MVP 不投入引导页 |
| 后台管理（Admin 页面） | P0 不需要，路由已移除 |

## 4. 用户画像与使用场景

### 4.1 典型用户画像

| 画像 | 特征 | 核心诉求 |
|---|---|---|
| **漫展扩列党**（主画像） | 20-30 岁，周末/节假日逛漫展，有固定 IP 偏好，想认识同担/同好 | 快速找到同场同好，安全建立连接 |
| **谷子交换党** | 收藏谷子，有出/求/换需求，怕被坑、怕被骚扰 | 低成本安全交易，联系方式可控 |
| **coser / 妆娘 / 画师** | 有个人作品或技能，想被同好发现、接到约稿 | 展示自我 + 被有需求的人找到 |
| **参展组织者 / 商户**（次要） | 发布漫展信息、维护场地 | 让活动信息被目标用户看到 |

### 4.2 核心使用场景

**场景 A：漫展现场扩列**
> 用户小王在漫展开场当天到达现场，打开 App 点"在场确认"（选日期+时段），发起一个 15 分钟同窗会"想认识同是《原神》厨的 coser"。系统优先匹配同时段在场的同好，小王看到一位匹配度 82% 的虚拟 ID `#AB12CD`，向其单向分享人设卡，对方授权后进入临时聊天。活动结束后聊天自动归档，双方点"成为新朋友吧"转为长期好友。

**场景 B：二手谷子交换**
> 用户小李想出一套《蓝色监狱》吧唧，在中谷店挂出（出 + 图片 + 邮寄）。买家小张在"谷子"tab 搜到，点"我想要"发起申请，双方私下转账后，小李确认发货（填运单号），小张收货后确认完成。全程平台不碰钱，联系方式仅在拍下后互相可见。

**场景 C：维护漫展信息**
> 组织者通过云端后台录入/更新漫展信息，App 用户无需刷新即可看到新漫展、时间/状态变更实时同步（Realtime），断网时显示缓存数据并提示。

### 4.3 情绪与安全诉求（女性安全，重点）

- 女性用户对线下社交与交易安全敏感，系统提供：NG 用户永远不进雷达、昵称隐私化（maskName 黑块）、L0 默认不暴露真实身份、举报按钮、24h 原文日志留存用于审核后物理删除。

## 5. 核心功能需求

### 5.1 功能全景图

```
                     ┌─────────────────────────────┐
                     │          人设卡             │
                     │ 基本资料 / 身份 / 兴趣 /     │
                     │ MBTI 星座 / 意图 / OC 卡     │
                     └──────────────┬──────────────┘
                                    │ tag 数据
              ┌─────────────────────┼─────────────────────┐
              │                     │                     │
     ┌────────▼────────┐   ┌────────▼────────┐   ┌────────▼────────┐
     │    漫展雷达      │   │   同窗会(临时)    │   │    中谷店       │
     │ 漫展列表/详情    │──▶│ 发起/加入/聊天    │   │ 挂出/浏览/关注   │
     │ 想去/在场确认    │   │ 解散/退出/升级    │   │ 状态机/申诉     │
     └─────────────────┘   └─────────────────┘   └─────────────────┘
```

### 5.2 P0 功能（已实现，验证阶段）

#### F1 人设卡编辑器（EditorView）

- **基本资料**（4 行 × 2 列网格）：
  - 第 1 行：CN/昵称（placeholder）+ 6 位编号 `#XXXXXX`（CodeField，只读态点击进编辑、实时大写、√/× 校验）
  - 第 2 行：性别（男/女/保密，3 等分 pill）+ 活动地区
  - 第 3 行：MBTI（16 种弹窗选择）+ 星座（12 种弹窗选择）
  - 第 4 行：签名（通栏，≤50 字，超长截断 + 提示）
- **头像**：上传到 Supabase Storage `kizuna-avatars`，≤5MB，PNG/JPG/WEBP/GIF；未上传时前端 fallback 小猫 `default-avatar.svg`
- **圈内身份**：最多 3 个多选（IdentityPicker）；**现实身份**：单选（学生/社畜/是阿宅喵/自定义）
- **兴趣图鉴**（InterestBuilder，18 分类 + 避雷 NG）：
  - 三态：A（未编辑，白底灰字）/ B（草稿，黑字灰徽章）/ C（已确认，黑底白字）
  - 每分类作品 ≤3，NG ≤10 且单标签 ≤20 字，支持自定义
- **扩列意图**（独立 IntentView）：想认识的人 / 想一起做的事 / 我能提供，各约 10 个预设 + 自定义
- **OC 卡**（OcEditorView）：OC 名字 / 简介 / 世界观 / 设定 / 立绘（3:4 或 1:1）/ 标签（≤10）/ 详细描述，实时预览

#### F2 首页（HomeView）

- quickTab：全部 / 漫展 / 同窗会（v-show + scrollIntoView，不跳页）
- 匹配 banner（同场 / 同想去看展 / 同城，3 头像 + 箭头 → /matches）
- 漫展 section（全部/进行中/即将开始 筛选 + 状态标）
- 同窗会 section（"我在的房间"高亮 + "正在进行的同窗会"）
- 断网红色 banner + 重试按钮

#### F3 漫展雷达

- **漫展列表/详情**（ExpoDetailView）：想去按钮（上限 10 个，触发器兜底）、在场确认弹窗（日期 + 时段 morning/afternoon/evening/all_day）
- **同窗会发起**（RadarLaunchView）：时间窗（3min/15min/1h/24h）、希望/提供（逗号分隔，≤10 个 ≤20 字）、线上/线下（线下需定位 + 地址）、可选密码（4-6 位数字）
- **同窗会房间**（RadarRoomView）：
  - 房主"解散"/参与者"退出"，密码门，参与者加入
  - 消息：发送状态机（sending/sent/failed + 感叹号重发）、HTML 转义、≤240 字、断网禁发
  - 房主解散走 60s 倒计时物理删除（供截图/举报留存）；参与者退出仅本地移除
- **匹配算法**（matching-v3）：五维 100 分 = 场景 30 + 兴趣 25 + 意图 20 + 身份 15 + 地区 10，4 桶分池（onSite/upcoming/city/global），NG 用户过滤，trust_score 加成最高 +4

#### F4 中谷店

- **挂出**（ZhongguFormView）：类型（出/求/换）、图片（≤9 张 ≤5MB）、IP 标签、角色、标题、价格、描述、标签、交易方式（邮寄/自提）、退换政策（7 选 1 + 运费承担）、收款码（微信/支付宝，含水印）
- **浏览**（ZhongguView）：搜索栏 + 5 tab（关注/推荐/服饰/道具/谷子）+ 双列网格 + 我的挂出快览
- **关注系统**（followStore）：关注卖家，第一时间看到其挂出；localStorage fallback
- **交易状态机**（zhongguMachine，XState 8 态）：见 7.2
- **申诉**（DisputeView）：理由（未收到/不符/缺陷/其他）+ 证据图

#### F5 消息（MessagesView）

- 4 tab：请求 / 想认识 / 对话 / 拒绝
- 请求流程：发起 → 接受（生成对话）→ 拒绝 / 取消
- Realtime：新请求 / 新消息提示 banner（5 秒消失）
- 对话（ConversationView）：临时（scope_id 绑定活动）→ 升级为好友（转持久）

## 6. 非功能需求

### 6.1 性能

| 指标 | 要求 |
|---|---|
| 首屏渲染 | 先读缓存快速渲染，避免白屏（expoStore 缓存优先） |
| 断网可用 | 漫展数据离线缓存，断网显示缓存 + 红色 banner |
| 构建产物 | PWA 预缓存 ~70 entries，Gzip 后 ~945 KB |
| 单文件 | ≤300 行（历史约定，HomeView 例外已超 1000 行） |

### 6.2 可用性 / 兼容

- 目标平台：Android（Capacitor 8 打包，模拟器 Pixel_7 / API 34 验证）
- 触控目标最小 44×44
- 支持 `prefers-reduced-motion`（减少动效）
- 字体：Noto Sans JP → Helvetica Neue 回退，全局 line-height 1.6

### 6.3 安全与隐私（核心）

| 要求 | 实现 |
|---|---|
| 平台不碰资金 | 无支付通道，私下转账 |
| 隐私分层（L0-L2） | 雷达默认不暴露真实姓名/头像/联系方式 |
| NG 用户过滤 | 雷达永不进入 NG 用户 |
| 昵称隐私化 | maskName（单字 X女士/X先生，≥2 字首字母+黑块） |
| 临时聊天删除 | 房主退出 60s 倒计时物理删除消息 + 房间；三层删除防护 |
| 24h 原文日志 | 留存用于审核，到期物理删除 |
| 举报 | 消息旁举报按钮 |
| 密钥安全 | Supabase ANON_KEY 不入库，.env.local 本地管理 |

### 6.4 可靠性

- 网络失败降级：Supabase 未配置时全部 Promise 化 mock，不阻塞渲染
- 离线状态机：消息 sending/sent/failed，失败可重发
- localStorage fallback：关注、想去/在场、UID 均有本地降级

### 6.5 可维护性

- 状态管理：聚合 store（kizuna.ts）代理 6 个子 store（user/listing/radar/expo/message/follow）
- 算法独立：matching-v3 / trustScore / virtualId / venue / zhongguMachine 均独立模块
- 类型定义集中在 mockData.ts

## 7. 业务逻辑与规则

### 7.1 人设卡规则

| 字段 | 规则 |
|---|---|
| CN/昵称 | 后端由 `auth.email.split('@')[0]` 自动生成，UI 可改 |
| 编号 | 6 位 `#XXXXXX`，默认纯数字可改字母数字；宽版重名检测（编号+昵称同时相同才冲突） |
| 性别 | 男/女/保密（无自定义） |
| 圈内身份 | ≤3 个多选；现实身份单选 |
| 兴趣分类 | 分类数无限制；每分类作品 ≤3；NG ≤10；单标签 ≤20 字 |
| 兴趣三态 | A（未编辑，不写库）→ B（草稿，写库不显示）→ C（已确认，写库 + 卡片显示） |
| 签名 | ≤50 字 |
| 头像 | ≤5MB，PNG/JPG/WEBP/GIF；未上传 fallback 小猫 |

### 7.2 中谷店交易状态机（XState 8 态）

```
active ──RESERVE──→ reserved ──SHIP──→ shipped ──COMPLETE──→ completed
  │                    │                  │                    │
  │                    ├──CANCEL──→ cancelled                  ├──DISPUTE──→ disputed
  │                    └──DISPUTE──→ disputed                  │
  ├──CLOSE──→ closed (终态)                                    │
  └──ARCHIVE──→ archived ──REACTIVATE──→ active                 │
                                       disputed ──RESOLVE──→ closed (终态)
```

| 事件 | 前置状态 | 目标状态 | 权限 |
|---|---|---|---|
| RESERVE（拍下） | active | reserved | 非卖家 |
| SHIP（发货） | reserved | shipped | 卖家，需运单号 |
| COMPLETE（收货） | shipped | completed | 仅买家 |
| CANCEL（取消） | reserved/shipped | cancelled | 买卖双方 |
| DISPUTE（申诉） | reserved/shipped/completed | disputed | 买卖双方，插 disputes 表 |
| RESOLVE（裁决） | disputed | closed | 平台 |
| CLOSE | active | closed | 卖家 |
| ARCHIVE（下架） | active | archived | 卖家（可重新上架） |
| REACTIVATE | archived | active | 卖家 |

### 7.3 退换政策（7 选 1）

| 值 | 标签 | 说明 |
|---|---|---|
| no_return | 不退不换 | 一旦发货不接退换 |
| 7d_defect | 7天质量问题 | 7天内质量问题可退 |
| 14d_defect | 14天质量问题 | 14天内质量问题可退 |
| 7d_mismatch | 7天描述不符 | 7天内与描述不符可退 |
| 14d_mismatch | 14天描述不符 | 14天内与描述不符可退 |
| 7d_full | 7天无理由 | 7天内无理由退 |
| 14d_full | 14天无理由 | 14天内无理由退 |

退货运费承担：卖家 / 买家 / 双方各半。

### 7.4 隐私可见度（4 层）

| 层级 | 内容 | 触发条件 |
|---|---|---|
| L0 | 仅"匹配度 X%" + 模糊维度标签 | 雷达候选池默认 |
| L0.5 | 虚拟 ID `#AB12CD` + 共同兴趣 + 同想去漫展 + 评分理由 | 雷达详情 |
| L1 | CN/昵称 + MBTI/星座/性别/地区 + 兴趣 C 态 + 意图 + 挂单 | 单向分享授权 |
| L2 | 联系方式（微信/QQ） | 双向互授权 |

### 7.5 雷达匹配规则

- 时间窗：3min / 15min / 1h / 24h（基于 `last_active_at` 过滤）
- 五维权重：场景 30 + 兴趣 25 + 意图 20 + 身份 15 + 地区 10
- 4 桶分池：onSite（同场同时段）/ upcoming（同想去）/ city（同去过/同城）/ global
- 自己的房间固定 100 分排最前
- NG 用户永远过滤
- trust_score 加成最高 +4

### 7.6 trust_score 公式

```
total = min(见面次数×3, 9) + min(中谷店成功×2, 6) + min(完成活动×1, 5)，上限 20
radarBonus = total / 20 × 4（最高 +4）
```

### 7.7 想去/在场规则

- 想去上限 10 个（触发器兜底）
- 在场确认：选日期 + 时段（上午/下午/晚上/全天）
- 在场确认后自动取消同展的"想去"
- 展结束后自动归档为 visited

### 7.8 同窗会临时聊天

- `scope='temporary'` 绑定 `scope_id`（venue_id）
- 活动结束进入"已结束"但保留记录
- "升级为好友"转持久（scope='persistent'）

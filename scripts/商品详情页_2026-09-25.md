# 中谷店商品详情页 设计与实现（2026-09-25）

## 目标

最新版中谷店点击商品进入 `/zhonggu/:listingId` 只有空壳占位（71 行，「商品详情正在设计中」）。
本次按买家视角 + 卖家视角完整实现商品详情页。

## 设计要点

### 信息架构（自上而下）
1. **图库** — 主图 1:1 + 右上角计数（`2 / 5`）+ 底部缩略图条，点击切换
2. **标题区** — 出/求/换 徽章 + 价格 + 包邮标 + 标题 + 成色 + 发布时间 + 想要数/浏览数
3. **作品信息** — IP 标签（主色 chip）+ 角色 + tags + attributes 键值表（品牌等）
4. **详细描述** — `white-space: pre-wrap` 保换行
5. **交易方式** — 邮寄显示「收件地址」（未拍下显示"拍下后可见"）+ 地址备注；自提显示自提地点
6. **退换政策** — 政策 label + desc + 退货运费承担 + 补充说明
7. **联系方式** — 微信/QQ；**仅卖家本人或已拍下买家可见**，否则显示"拍下后才会看到卖家的联系方式"
8. **卖家** — 头像（fallback 小猫 default-avatar.svg）+ CN + 编号 + MBTI/星座/地区 + 关注按钮
9. **卖家管理区**（仅 owner）— 编辑挂出 / 下架 / 重新上架
10. **买家申诉区** — reserved/shipped/completed 状态显示「发起申诉」跳 `/:id/dispute`
11. **底部说明** — "绊不碰资金 · 不担保交易 · 请自行核实后再转账"

### 底部操作栏（非 owner）
- 左：关注卖家 / 已关注（34% 宽）
- 右：**我想要**（主按钮，仅 status==='active' 可点，否则显示状态 label 并禁用）

### 我想要弹窗（Teleport 到底部 sheet）
- 默认预填 `想收「{title}」，还在吗？`
- 200 字上限 → 调 `store.createRequest(currentUserId, owner_id, msg, listingId)` → 成功跳 `/messages`

### 状态徽章配色（头部右侧）
- active 绿 / reserved 琥珀 / shipped 蓝 / disputed 橙 / 其他中性灰

### 设计规范
遵循 MUJI 校准：`#3c3c43` 主文字 / `#f7f5f0` 米色 / `#f4eede` Kinari / 圆角统一 4px / 边框 `#eee` / 阴影 `0 2px 8px rgba(0,0,0,0.03)` / 价格红 `#c44545` / sticky 头部与底部栏 + safe-area 适配。

## 技术实现

**文件**：`src/views/ZhongguDetailView.vue`（71 行 → 22,565 字节 / 约 700 行）

**数据来源**：`store.fetchListing(id)` → 从 `store.listings` 中匹配（`listingStore.fetchListing` 单查并更新/推送本地）

**关键兼容处理**：
- `images` 字段未在 `ZhongguListing` 类型定义中，但表单（ZhongguFormView）确实写入 `images: string[]`，卡片也用 `(props.listing as any).images` 读取 → 详情页同样用 `as any` 兼容读取
- 卖家信息用 `store.getUserByIdLocal(owner_id)`（本地优先，避免额外网络请求）
- MBTI 用 `getMbtiName()`，星座用 `normalizeZodiac()`（兼容旧中文数据）
- 头像 fallback：`avatar_url` 为空或含 `placehold.co` → 用 `/default-avatar.svg` 小猫
- `canSeeContact = isOwner || isBuyer`（`reserved_by === currentUserId`）
